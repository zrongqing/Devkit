# 统一分页查询

前后端默认使用服务端分页、组合筛选与多列排序。基础 UI 使用 Element Plus。既有 GET 列表契约保留，供选择器和旧调用方使用；新版 Web 表格使用新增的 POST `.../query`，不再下载完整列表后在浏览器筛选。

## 公共层

- Domain：`Devkit.DomainCommons.Querying.IPagedQueryStore`、`PageQuery`、`PageResult<T>` 和 `PageQueries`。
- Infrastructure：三个服务的 DbContext 统一继承 `PagedDbContext`。`PageAsync<T>(query, scope, ct)` 默认可查询每张映射表的标量字段，保留软删除过滤器，必须传入授权范围。通过 EF 主键元数据补齐单键或组合键稳定排序。
- HTTP 通过应用服务公开授权 DTO，不接受任意表名、实体名或 SQL。身份查询仅返回 `AccountView` / `RoleView` 等投影，认证令牌、密码哈希和内部导航对象不在字段范围中。

默认每页 20 条，1–100 条合法。页码从 1 开始。最多 32 个筛选条件、8 个用户排序字段，每个筛选值最多 512 字符。无效字段、方向、操作符、参数返回 400 ProblemDetails，`code=invalid_query`；未登录 401，无权限 403，父资源不存在或不可访问 404。越界页返回空 `items` 和真实 `total`，Web 自动请求最后一页。

## 请求与响应

```json
{
  "page": 1,
  "pageSize": 20,
  "filters": [
    { "field": "name", "operator": "contains", "value": "制度" },
    { "field": "description", "operator": "contains", "value": "考勤" }
  ],
  "sorts": [
    { "field": "name", "direction": "asc" },
    { "field": "createdAtUtc", "direction": "desc" }
  ]
}
```

响应沿用 `ApiResponse` 包装：`{ "data": { "items": [], "total": 0, "page": 1, "pageSize": 20 }, "traceId": "..." }`。`total` 为全部授权数据在所有筛选条件生效后的数量。多个条件按 AND 生效，排序优先级与数组顺序一致，再补唯一键。字符串支持 `contains` / `eq`，标量支持 `eq` / `gte` / `lte`，普通标量的默认 `contains` 按类型转换后精确匹配；日期使用 ISO 8601，数值使用不带千位分隔的原始值。查询值始终以表达式参数处理，不拼接 SQL。

## 已接入入口

| 服务 | POST 路径（均以 `/api/v1` 开头） | 上下文 |
| --- | --- | --- |
| Business | `/exam-study/knowledge-bases/query`、`/exam-study/projects/query` | `?all=true` 仅管理员可跨用户查询 |
| Business | `/exam-study/knowledge-bases/{id}/sources/query` | 资料受父知识库访问权约束 |
| Business | `/exam-study/questions/query` | 可带 `knowledgeBaseId`、`all` |
| Business | `/exam-study/jobs/query` | 全部授权业务任务，不受旧 GET 的 200 条截断 |
| Business | `/exam-study/projects/{id}/mistakes/query`、`/exam-study/projects/{id}/attempts/query` | 受项目访问权约束；学习记录使用摘要 DTO，避免暴露试卷答案 |
| FileStorage | `/files/query`、`/files/{id}/references/query`、`/storage/jobs/query` | 保留文件所有权与模块权限 |
| Application | `/identity/users/query`、`/identity/roles/query`、`/identity/users/disabled/query` | 可带 `?module=权限编码` 用于派生授权列 |
| Application | `/identity/organization/departments/{id}/positions/query` | 同时支持 `members` 姓名字段 |
| Application | `/identity/audit/query` | 查询全部审计记录，不受旧 GET 的 50 条游标限制 |
| Application | `/web/menu-management/menus/query` | 按顶层节点分页，`total` 统计根节点；`items` 包含该页根节点及其后代，Web 仅重建层级 |
| Application | `/web/menu-management/compare/query` | 请求为 `{menus: 前端声明, query: PageQuery}` |
| Application | `/web/menu-management/fields/query` | 请求为 `{menus, menuCode, query}`，服务端重新计算字段比较 |

菜单树筛选保留匹配节点的祖先，排序在同级显示顺序中生效。删除资格使用完整菜单快照判断，不能依据被筛选后的孩子数量判断。接口新增不会改变旧列表返回形状；本次未改 Desktop，旧调用继续兼容，新分页能力需要 Desktop 后续显式接入。

## 派生列与执行位置

项目 `knowledgeBases`、错题 `question`、职位 `members`、角色权限与菜单授权汇总等字段由服务端登记。用户侧支持 `directModuleGrant`、`effectiveModuleGrant`、`userMenuCounts`，角色侧支持 `roleModuleGrant`、`roleMenuCount`；菜单字段比较使用 `localValue`、`lastSyncedValue`、`currentValue`。状态和题型支持中文展示名称以及原始编码。

普通业务 / 文件 / 审计查询在数据库过滤、计数、排序、分页。跨实体派生字段、中文状态筛选、权限汇总与菜单树在服务端完整授权快照中处理，再返回一页；这些视图仍有加载完整快照的成本，数据规模增大时应提供专门数据库投影或索引，不能改为浏览器筛选。

## Web 组件

`DataTable` 必须提供 `load-page`，`query-context` 变化时回到第一页，数据变更后刷新当前页。输入框后的筛选图标一次提交所有列草稿，多列条件一起请求。上下三角选择升 / 降序，重复点击当前方向取消该列排序，数字标记排序优先级。取消请求并用序号忽略过期响应；失败显示错误与重试。顶部保留业务选项、条件标签、刷新和表格设置，不提供通用搜索框或筛选按钮；列头显示分割线，筛选及排序按钮始终显示，生效状态蓝色高亮，底部仅显示总数及分页。行内容默认水平左对齐、垂直居中。“表格设置”管理显示列、固定位置、自动适应与重置；默认固定首个关键数据列和右侧操作列，窄屏解除固定。固定与列宽偏好独立于查询。

验证包含独立 SQLite 数据库 / 文件目录与受控外部服务替身，覆盖组合筛选、排序稳定性、翻页、权限、所有权、无效输入、文件引用、审计与任务超过旧截断阈值以及菜单祖先保留。
