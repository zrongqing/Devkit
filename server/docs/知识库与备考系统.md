# 知识库、备考与文件存储

实现位于现有 .NET 10 服务端和 Vue 3 Web 中，按业务模块隔离。Desktop 页面不在本次范围，调用模板同步维护于 `client/templates/WorkspaceApi.http`。接口事实来源是运行中的 `/openapi/v1.json`，Swagger 在 `/swagger`；Web 调用集中于 `web/src/api/examStudy.ts`。

## 启动

在仓库根目录使用 PowerShell，依赖 .NET 10、Node.js、SQL Server 和 Docker Desktop：

```powershell
./server/scripts/Start-StudyDependencies.ps1

# 创建 / 更新数据库。沿用服务端现有配置或 ConnectionStrings__Default 环境变量。
dotnet tool restore
dotnet ef database update --project server/src/Devkit.Server.Infrastructure --startup-project server/src/Devkit.Server.Api

# 启动 API。自动在 D 盘创建独立配置文件，不覆盖已有配置。
./server/scripts/Start-StudyServer.ps1
```

另一个终端启动 Web：

```powershell
cd web
npm ci
npm run dev
```

Web 默认 `http://127.0.0.1:5173/#/login`，API 默认 `http://localhost:12511`。Web 使用 `VITE_API_BASE_URL` 指定 API 地址；跨域来源须同时加入后端 `Cors:AllowedOrigins`。Redis 默认 `localhost:6379`，Qdrant REST 默认 `localhost:6333`、gRPC 默认 `localhost:6334`；三个端口仅绑定本机回环地址。

首次数据库初始化默认创建 **admin / admin**，角色 Administrator。登录后可在“系统设置”修改密码。修改后的密码不会被启动程序重置；已存在的同名账号不会被覆盖。普通用户由“账号与权限”创建，内置 User 角色不默认授予知识库权限。注册入口仍受现有 Registration 配置控制。

## 使用流程

1. 创建知识库，上传文本 PDF、DOCX 或补充手动正文。PDF 最多 500 页，默认单文件 20 MiB、正文 200 万字。文件标题、提取正文可以修正；每次修改保留独立历史版本。
2. 在“处理任务”查看提取和索引状态。先按章节、条款、段落、表格行拆分，保留 PDF 页码或 DOCX 段落 / 表格位置。长条目按标点拆分并保留重叠上下文。
3. 创建备考项目，关联同一用户的一个或多个知识库。“快速查原文”支持 Enter 搜索、`/` 聚焦、知识库筛选、复制原文及打开来源。
4. 手动录题，或用 AI 生成草稿。单选、多选、判断题均须审核后才可用于练习。来源更新后，已审核引用题标记为“待复核”。重新审核须选用当前版本引用。
5. 在项目内顺序 / 随机练习、重练错题，或创建限时模拟考试。考试在服务端计时和判分；试卷保存题目与出处快照，交卷前不返回正确答案。学习记录可恢复未完成考试。

旧版 `.doc` 请先另存为 `.docx`。扫描 PDF 需要先做 OCR；当前实现不附带 OCR 引擎。缺少可提取文字的页会给出提示。DOCX 引用使用段落和表格位置，不虚构打印页码；复杂排版和自动编号可能需要人工校正。手动校正内容与原文件均保留。

## 模型与检索

`Start-StudyServer.ps1` 使用 `D:\.server data\devkit\config\workspace.json`，样例位于 `server/deploy/exam-study/workspace.example.json`。直接启动 API 时设置 `DEVKIT_CONFIG_FILE` 为该文件的绝对路径即可加载。配置变更后重启 API；环境变量覆盖文件配置。

| 配置 | 用途 |
| --- | --- |
| `Workspace:Chat:BaseUrl / Model / ApiKey` | 兼容 `/chat/completions` 的对话模型，用于问答和生成题目 |
| `Workspace:Embedding:BaseUrl / Model / ApiKey` | 兼容 `/embeddings` 的向量模型，用于语义分块及检索 |
| `Workspace:QdrantUrl / QdrantApiKey` | Qdrant REST 地址和可选密钥 |
| `Workspace:DataRoot` | 初始文件位置及日志、临时文件、导出、备份的统一根目录 |
| `Workspace:MaximumUploadBytes / MinimumFreeBytes` | 上传上限与最低预留空间 |

BaseUrl 填 API 根地址，如服务商要求 `/v1` 则包含 `/v1`，不附加具体操作路径。模型可部署在本机或使用支持兼容协议的服务。资料片段会发送给配置的模型服务。未配置模型时，关键词检索、手动录题和练习照常使用；语义任务停在“待配置”。

关键词检索使用 Qdrant 原生 BM25 多语言分词，关闭英文词干和停用词处理。语义增强会按相邻段落的向量相似度合并片段，再与 BM25 结果通过倒数排名融合。两条路径都在 Qdrant 内过滤所有者、关联知识库与当前发布版本，服务端返回前再次校验范围。向量维度与模型配置标识隔离，切换模型后到资料列表选择“重建索引”。Qdrant 故障会返回明确错误，修复后可以重试索引任务。

问答只携带检索出的资料片段，保留编号引用；题目生成只允许引用提供的片段 ID，输出草稿由人审核。引用校验可以防止不存在的出处，无法自动保证模型解释正确。

## 文件模块与迁移

原件按 `files/yyyy/MM/<FileId>.bin` 保存，原文件名和 SHA-256 存在数据库。业务代码只保存 FileId，不保存物理路径。文件下载经过登录、权限与所有者检查，不暴露公共磁盘 URL。通用上传 `purpose=general` 与知识库上传 `purpose=exam-study` 共用 IFileService；其他业务可通过该接口维护 FileReference，并在业务事务内完成关联 / 解关联。

资料归档只解除业务引用，原件继续保留。文件管理可查看引用记录，只有管理员能明确永久删除无引用文件。尚有迁移副本或正在上传的文件不允许删除。

迁移步骤：

1. 管理员打开“存储与迁移”，登记另一个可写绝对路径。系统拒绝路径重叠、磁盘根目录及重解析链接。
2. 发起迁移，新的上传切换到目标存储。每个已有文件依次复制、核对长度和 SHA-256，再更新数据库中的 LocationId，FileId 不变。
3. 查看任务状态。中断后重启服务或重试任务，会跳过已切换文件并继续处理；源文件始终保留到独立清理步骤。
4. 迁移完成、确认读取正常后，点击“校验并清理旧副本”。此操作再次校验有效副本并删除旧副本；被读取的文件会保留等待重试。

迁移和清理任务互斥。清理失败时先恢复路径 / 空间 / 读取条件后重试，不能直接手动移动或删除存储目录。数据库中的 StorageLocations 是已有文件的定位依据；只修改 DataRoot 不会迁移已有文件。从旧目录切换到 `D:\.server data\devkit` 时，先复制旧数据并通过“存储与迁移”创建新位置、迁移文件，确认读写后再清理旧副本。以后调整其他持久目录也应保留在统一根目录下。

## Docker 持久化和备份

统一的 `compose.yaml` 位于仓库根目录，包含服务端、Qdrant `v1.19.1` 和 Redis `8.0`。Docker Desktop 磁盘保留在 C 盘。Qdrant 的 `/qdrant/storage` 和 `/qdrant/snapshots` 分别使用固定名称的 Docker 命名卷 `devkit_qdrant-data`、`devkit_qdrant-snapshots`，由 Docker Linux 文件系统保存；不将 Qdrant 数据直接绑定到 Windows 目录。这遵循 [Qdrant 对不兼容文件系统的处理建议](https://qdrant.tech/documentation/common-errors/#incompatible-file-system)。

Redis 的 `/data` 仍绑定到 `D:\.docker data\redis`，服务端的 `/var/lib/devkit` 绑定到 `D:\.server data\devkit`。`DEVKIT_DOCKER_DATA_ROOT` 只控制 Redis 的宿主机数据目录，不改变 Docker Desktop 的磁盘位置。运行 `./server/scripts/Start-StudyDependencies.ps1` 即可启动 Qdrant 和 Redis，无需移动 Docker 磁盘。`docker compose down` 保留命名卷；不要使用 `down -v` 清理需要保留的数据。

在 Windows 上使用 `Start-StudyServer.ps1` 时，存储位置记录为 Windows 绝对路径。若改用 Compose 中的 Linux `devkit-server` 容器，应使用独立数据库并让它以 `/var/lib/devkit` 初始化存储位置；不要让 Windows 进程与 Linux 容器共用包含不同平台绝对路径的 StorageLocations。

一致性备份应同时覆盖 SQL Server 数据库、所有有效 StorageLocations 和 Qdrant 快照。迁移不是备份。备份默认放在 `D:\.server data\devkit\backups`，之后可复制到独立备份设备。Qdrant 丢失后可从数据库片段和保留的原文重建索引；数据库中的题库、练习记录、文件定位和所有者信息不可由 Qdrant 恢复。

## 权限和接口

| 权限 | Web 菜单与服务端操作 |
| --- | --- |
| `exam-study.access` | 知识库、题库、项目、查询、练习、处理任务 |
| `system.files.manage` | 通用文件管理；普通角色只能访问自己的文件 |
| `system.storage.manage` | 全服务存储位置与迁移，应仅授予可信维护人员 |
| `system.identity.manage` | 用户及角色管理，管理员角色的授予和停用仅允许 Administrator |

Administrator 绕过权限和所有者限制。普通用户即使猜出对象 ID 也不能读取其他人的知识库、题库、试卷或文件。菜单与每次 API 请求分别鉴权，角色修改后需刷新菜单；被禁用账号和密码修改会使原会话失效。

所有接口使用 `/api/v1`。成功响应是 `{ data, traceId }`；异步入库 / 生成 / 迁移返回 202；失败使用 ProblemDetails，包含 `code` 和 `traceId`。更新对象必须携带当前 `revision`，并发冲突返回 409。

| 路径组 | 主要资源 |
| --- | --- |
| `/exam-study/knowledge-bases`、`/sources` | 知识库、来源、版本、片段与重建索引 |
| `/exam-study/projects` | 关联范围、检索、问答、历史、学习进度与组卷 |
| `/exam-study/questions`、`/generation-jobs` | 题库、审核和 AI 草稿 |
| `/exam-study/attempts`、`/mistakes` | 作答、交卷、错题掌握状态 |
| `/exam-study/jobs`、`/capabilities` | 任务、重试与外部能力状态 |
| `/files`、`/storage` | 上传、下载、引用、删除、存储位置和迁移 |
| `/identity`、`/auth/permissions`、`/auth/password` | 账号、角色、当前权限和修改密码 |

后台任务持久化在 SQL Server，使用租约防止重复领取，失败最多自动尝试三次，可手动重试。生成草稿以任务 ID 防重；考卷保存快照并由事务完成判分。当前针对个人 / 小团队部署，列表返回有界任务及问答历史，知识库列表和片段加载未做大规模分页优化。

## 模块导航与授权（2026-09）

Web 使用数据库多级菜单：知识库下包含项目管理、知识库管理、知识检索及刷题目录（刷题与模拟考、题库管理、错题与学习记录）；系统管理下包含用户管理目录（用户、角色、权限）、菜单管理、基础参数、文件管理、存储与迁移及关于 Web；系统监控包含运行状态和处理任务。原路由及业务数据保留，具体声明、授权和同步契约见 [菜单管理与同步](菜单管理与同步.md)。

导航显示入口在顶部右侧，支持展开、仅图标、完全隐藏三种状态；完全隐藏后左侧保留展开按钮。偏好保存在当前浏览器，移动端保持抽屉导航。

权限目录由 `GET /api/v1/identity/permissions` 返回，每项包含 `key / name / group / routeKey`。菜单和直接路由按独立的 `menu:web` 声明鉴权；业务接口继续按业务权限鉴权。授予业务权限不再自动授予菜单。首页、基础参数入口和关于页保留公共入口；基础参数中的存储修改仍要求存储权限，密码修改要求登录。系统监控需要 `system.monitor.view`。

- `study.projects.manage`：项目与关联范围维护。
- `study.knowledge.manage`：知识库、资料与索引维护。
- `study.search`：项目检索、问答与查询历史。
- `study.practice`：刷题、考试、错题与进度；进度返回 `questionNames`，从本人试卷快照提供题干，不必授予题库管理权限。
- `study.questions.manage`：出题、审核和题库维护。
- `study.jobs.view`：处理任务查看；重试另要求相应知识库 / 出题 / 存储权限。
- `system.users.manage`：用户基本信息维护；`system.roles.manage`：角色信息和授权维护；`system.permissions.manage`：用户角色分配、用户直接授权、角色授权。
- 原 `system.files.manage` 与 `system.storage.manage` 继续使用。

有效权限为用户直接授权和全部角色授权的并集。取消直接授权不会覆盖继承授权。旧 `exam-study.access` 展开为全部学习模块，旧 `system.identity.manage` 展开为三个身份管理模块；旧数据无需迁移。新界面保存时将旧整体授权转换为明确模块授权，以支持单独撤销。Administrator 拥有全部权限（包括后续新增模块），不能修改内置角色或移除最后一个管理员。非管理员不能分配超出自己权限范围的授权，也不能修改管理员账号。

新增接口：`PUT /api/v1/identity/users/{id}` 接受 `{ userName, email }`；`PUT /api/v1/identity/users/{id}/permissions` 接受 `{ permissions: string[] }`，空数组撤销全部直接权限。用户列表新增 `permissions`（直接）及 `effectivePermissions`（最终）字段。权限编辑后每个请求读取数据库中的当前授权，Web 刷新权限快照与菜单；角色分配仍沿用会话失效机制。共享知识库列表及项目列表服务于检索 / 刷题选择器，列表可读不授予编辑权限。

`GET /api/v1/system/runtime` 返回 `info`、`startedAtUtc`、`uptimeSeconds`、`workingSetBytes`、`managedMemoryBytes`、`threadCount`、`processorCount`、`totalProcessorSeconds`。指标是服务进程数据，不是整台宿主机资源占用。Web 每 30 秒采样，仅在监控页可见时刷新；失败保留上次采样并显示过期提示。数据库与 Redis 就绪检查继续使用部署健康端点 `/health/ready`。

Web 调用模板集中于 `web/src/api/examStudy.ts`、`web/src/api/system.ts`；Desktop 对应 `client/templates/WorkspaceApi.http`。部署时需同时更新 API 和 Web；OpenAPI 由 DTO 与端点自动生成。
