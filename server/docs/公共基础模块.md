# 公共基础模块

参考 [aspnet-demo-englishLearnning 的 Commons 组织方式](https://github.com/zrongqing/aspnet-demo-englishLearnning/tree/main/src/aspnet-demo-english-webapi/Commons)，将重复的技术能力集中到 `server/src/Commons`。这是按当前 .NET 10 项目重新整理的实现，继续使用现有依赖版本；未引入参考项目中的 MediatR、事件总线、自动实体扫描或整套启动框架。

## 模块与职责

| 项目 | 公共能力 | 主要调用方 |
| --- | --- | --- |
| `Devkit.Commons` | JSON 序列化、带状态码与错误码的服务异常基类 | Application |
| `Devkit.DomainCommons` | UUIDv7 主键、审计字段、软删除实体基类 | Domain |
| `Devkit.Infrastructure` | 审计与软删除拦截器、显式 SQL Server 注册、数据库就绪检查、RSA PEM 加载与 KeyId | Infrastructure |
| `Devkit.AspNetCore` | 响应信封、ProblemDetails、JWT Bearer 验证参数、端点发现、CORS、OpenAPI、健康路由、配置加载 | Api |

`Devkit.Commons` 与 `Devkit.DomainCommons` 不引用 ASP.NET Core 或 EF Core。公共项目不能引用 Identity、FileStorage 或 Business；上下文内部仍保持 `Api -> Infrastructure -> Application -> Domain`。Api 公共库依赖技术基础库以处理数据库并发异常，技术基础库只向下引用公共实体基类。

`ApiResponse<T>` 的 CLR 类型集中到公共库；对外 JSON 仍为 `{ data, traceId }`，错误仍为包含 `code / traceId` 的 ProblemDetails。端点专属请求与响应继续在各 API 的 `Contracts` 中维护，OpenAPI 仍是跨端 HTTP 契约来源。

## 使用方式

各 API 在 `Program.cs` 中显式传入自己的环境变量名与端点程序集：

```csharp
builder.AddDevkitExternalConfiguration("DEVKIT_BUSINESS_CONFIG_FILE", args);
builder.Services.AddDevkitApi(builder.Configuration, typeof(Program).Assembly);
// 注册本服务的认证、授权和应用服务后构建。
var app = builder.Build();
app.UseDevkitApi();
app.MapDevkitApi("Devkit Business API");
```

公共库只扫描传入的端点程序集。Identity 的限流仍由自身注册，通过 `beforeAuthentication` 回调保留中间件顺序；Business 自行注册和映射 Controller。公共 JWT 扩展仅统一签名、issuer、audience、有效期和认证失败响应，令牌版本验证与远程权限断言仍分别由各宿主实现。

数据库注册保留显式类型和连接键：

```csharp
services.AddDevkitSqlServer<BusinessDbContext>(configuration, "Business");
```

该扩展添加 SQL Server 重试、审计拦截器和数据库 readiness 检查。Identity 通过可选回调配置自己的播种行为；各自的 DbContext、实体映射、查询过滤器、迁移、数据所有权均由上下文维护。扩展不会自动迁移或创建数据库。

RSA 加载器统一检查 PEM 和至少 2048 位密钥，并生成相同规则的 KeyId。Identity 的密钥包装类仍独占私钥和签发行为，Business 的包装类仍只加载公钥并拒绝私钥 PEM。

## 领域边界

公共实体基类只表达技术字段，不定义共同业务模型。用户、角色、权限分配、导航属于 Identity；备考、文件、模块属于 Business。Actor、权限目录、业务异常类型、仓储抽象和应用服务继续由各上下文维护。`IdentityException` 与 `BusinessException` 仅共用异常元数据基类，不共享业务规则。

跨上下文仍通过版本化 HTTP 权限断言关联，不直接引用对方项目或访问对方数据库。后续公共模块的变更需同时验证各宿主，避免把某一服务的业务规则逐步放入 Commons。

## 验证与发布

```powershell
dotnet build server/Devkit.Server.slnx
dotnet test server/Devkit.Server.slnx
```

测试使用隔离数据库和外部服务替身，验证审计历史、更新与软删除、RSA 签发/验证职责、两宿主 CORS、存活与就绪检查以及公共程序集的依赖边界；现有接口与契约测试继续覆盖原有行为。

各服务 Dockerfile 均显式复制 Commons 项目用于 restore，再复制公共源码用于 publish。最终镜像包含本上下文及所需公共程序集，不包含其他上下文。公共库随各镜像发布，当前无需单独 NuGet 发布或运行公共服务。

FileStorage 作为第三个独立上下文使用同一套 Commons，领域与配置边界见 [文件服务独立部署](文件服务独立部署.md)。
