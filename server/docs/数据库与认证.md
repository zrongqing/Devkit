# 数据库与认证

身份与业务现在拥有独立 DbContext、迁移和连接配置，部署细节见 [认证与业务分离部署](认证与业务分离部署.md)。

- Identity：`server/src/Identity/Devkit.Identity.Infrastructure/Persistence`，连接键 `ConnectionStrings:Identity`。身份实体、角色授权、导航菜单与刷新令牌仅由此服务持有。
- Business：`server/src/Business/Devkit.Business.Infrastructure/Persistence`，连接键 `ConnectionStrings:Business`。备考、文件、作业和模块实体不引用身份实体，用户关联只保存 ID。
- 每个上下文分别维护 `Persistence/Migrations/SqlServer` 和模型快照。数据库可共用一台 SQL Server，但使用不同数据库及受限账号。

迁移必须明确指定上下文；脚本恢复执行前的环境变量，不输出连接串。普通迁移不播种管理员；Identity 启动时执行自己的初始化。

```powershell
./server/scripts/Update-Database.ps1 -Context Identity -ConnectionString '<身份目标连接串>'
./server/scripts/Update-Database.ps1 -Context Business -ConnectionString '<业务目标连接串>'
```

如确需迁移时创建管理员，可在 Identity 命令中明确使用 `-SeedBootstrapAccount`，并通过外部环境变量提供 `BootstrapAccount__UserName`、`BootstrapAccount__Email`、`BootstrapAccount__Password`。不得向 Business 播种身份数据。

认证协议保留 `/api/v1/auth/*` 版本路径、短期 access token、哈希存储且单次轮换的 refresh token 和 ProblemDetails 错误响应。签名统一采用 RS256，Identity 仅持私钥，Business 仅持公钥；旧 HS256 配置不再适用。

业务每次受保护请求通过 `GET /api/v1/auth/permissions` 获取当前身份断言，身份服务负责检查 `auth_version` 和账号状态；业务本地执行能力及资源归属规则。业务不直读身份表或身份缓存。

旧合并数据库升级请按部署文档停机备份并将数据复制到两个空目标库，不直接执行新初始迁移覆盖旧库。旧迁移历史仅归档于 `server/legacy`，生产程序不引用它。
