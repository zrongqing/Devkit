# 数据库与认证

## 数据模型

`User`、`Role`、`UserRole`、`RefreshToken` 都继承 `AuditableEntity`，包含：

- `Id`：应用侧 `Guid.CreateVersion7()` 生成的时间有序 UUID。
- `CreatedBy`、`UpdatedBy`：可空 UUID；系统任务没有登录用户时为空。
- `CreatedAtUtc`、`UpdatedAtUtc`：应用侧统一写入 UTC。
- `IsDeleted`：软删除标记；EF Core 全局过滤器默认排除已删除数据。

`AuditingSaveChangesInterceptor` 在保存时自动维护审计字段，并将 EF 的 Delete 操作改为软删除。不要在业务代码中依赖 SQL Server 的 `NEWID()`、服务器本地时间或数据库默认值。

## 迁移

工具版本通过 `server/.config/dotnet-tools.json` 固定。迁移不会随 API 启动自动执行，部署前显式运行：

```powershell
server/scripts/Update-Database.ps1 `
  -ConnectionString "Server=localhost;Database=Devkit;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True"
```

也可以设置 `ConnectionStrings__Default` 后直接运行 `dotnet ef database update`。生产发布应把迁移作为单独步骤，只运行一次，避免多个 API 副本同时迁移。

## 认证行为

- 注册需要用户名、邮箱和密码；密码至少 12 位，并包含大小写字母和数字。
- 用户名和邮箱均标准化后建立唯一索引；登录时两者都可作为账号。
- 密码由 ASP.NET Core `PasswordHasher<User>` 哈希，不保存或记录明文。
- 连续失败 5 次锁定 15 分钟；登录和注册另有每 IP 每分钟 10 次的 HTTP 限流。
- access token 默认 15 分钟，包含 subject、JWT ID、用户名、邮箱、角色和认证版本。
- refresh token 默认 7 天，只保存 SHA-256 哈希；每次刷新必须轮换。重复使用已经被替换的 token 会撤销该用户全部会话。
- `logout` 撤销单个 refresh token；`logout-all` 同时递增认证版本，使已签发的 access token 立即失效。

开发环境通过 User Secrets 设置签名密钥：

```powershell
dotnet user-secrets set "Jwt:SigningKey" "replace-with-at-least-32-random-bytes" `
  --project server/src/Devkit.Server.Api/Devkit.Server.Api.csproj
```

如需创建首个管理员，在 User Secrets 或生产密钥系统中配置：

```text
BootstrapAccount:Enabled=true
BootstrapAccount:UserName=administrator
BootstrapAccount:Email=administrator@example.com
BootstrapAccount:Password=<strong secret>
```

API 启动时只补齐 `Administrator`、`User` 角色和可选管理员，不会创建或升级数据库表。因此必须先执行迁移。

## 后续增加 MySQL 或 SQLite

1. 添加与 EF Core 主版本匹配的 provider。
2. 在 Infrastructure 的数据库注册处根据 `Database:Provider` 选择 `UseMySql` 或 `UseSqlite`。
3. 为每个 provider 使用独立迁移目录和设计时工厂，不共用 SQL Server 迁移。
4. 用该 provider 运行全部认证集成测试，重点核对唯一索引、UTC 时间、Guid 存储和迁移限制。

当前模型刻意不使用 schema、sequence、rowversion、数据库生成 UUID 或 provider 专用 SQL。SQLite 对类型和迁移仍有自身限制，接入前应参考 [EF Core SQLite 限制](https://learn.microsoft.com/en-us/ef/core/providers/sqlite/limitations)。SQL Server 配置依据 [EF Core SQL Server provider](https://learn.microsoft.com/en-us/ef/core/providers/sql-server/)。
