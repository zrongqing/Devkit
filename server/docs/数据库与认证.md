# 数据库与认证

Identity、Business、FileStorage 是三个独立服务，共用同一 SQL Server 实例中的同一个 `Devkit` 数据库。每个服务保留自己的 DbContext、实体模型和迁移，通过 HTTP 调用其他服务；共库不授权跨服务直接访问对方的表。

## 统一数据库配置入口

唯一连接键为 `ConnectionStrings:Devkit`。`server/database.json` 保存无凭据的本机开发默认值：

```json
{
  "ConnectionStrings": {
    "Devkit": "Server=localhost;Database=Devkit;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True"
  }
}
```

该文件由公共基础设施项目复制到 API、EF 工具的输出和发布目录，不要修改生成的副本。自定义环境在仓库外维护一份同结构 JSON，并为三个 API 及迁移工具设置相同的 `DEVKIT_DATABASE_CONFIG_FILE` 绝对路径。数据库配置优先级为：统一默认文件 → 统一外部文件 → `ConnectionStrings__Devkit` 环境变量 → `--ConnectionStrings:Devkit=...` 命令行。旧的 `ConnectionStrings:Identity` / `Business` / `FileStorage` 不再读取，应将实际连接迁至统一键。

```powershell
# 初次创建目录和文件；已有文件时直接编辑，不要覆盖。
New-Item -ItemType Directory -Force 'D:/.server data/devkit/config'
Copy-Item ./server/database.json 'D:/.server data/devkit/config/database.json'
$env:DEVKIT_DATABASE_CONFIG_FILE = 'D:/.server data/devkit/config/database.json'
```

VS F5 需在启动 VS 前设置环境变量，或配置 Windows 用户环境变量后重启 VS。真实连接串不得写入仓库。运行和 EF 设计时共用连接校验：必须明确 Server、Database，拒绝附加数据库文件；无效或缺失连接、显式指定的文件不存在都会报错，校验错误不输出连接串。

Compose 的 `.env` 只配置 `DEVKIT_DATABASE_CONFIG_FILE`，将同一文件只读挂载给三个 API，不再使用三个 `DEVKIT_*_SQL_CONNECTION_STRING` 变量。容器访问宿主机 SQL Server 时，将统一文件中的 Server 改为 `host.docker.internal,1433` 并使用有权访问 `Devkit` 的 SQL 登录；文件内容不经过 Compose 插值。主机迁移工具需使用适合其网络的 Server 地址，同时指向同一个实际数据库。开发与生产应使用不同实例或独立环境配置。

## 数据库迁移

三个上下文分别维护 `Persistence/Migrations/SqlServer`，在共用的 `__EFMigrationsHistory` 中使用不同迁移 ID。依次运行以下命令，勿并发迁移；API 启动不自动执行迁移：

```powershell
./server/scripts/Update-Database.ps1 -Context Identity
./server/scripts/Update-Database.ps1 -Context Business
./server/scripts/Update-Database.ps1 -Context FileStorage
# 可显式指定同一份统一配置文件：
./server/scripts/Update-Database.ps1 -Context Business -DatabaseConfigFile 'D:/.server data/devkit/config/database.json'
```

`-ConnectionString` 保留为本次命令对共享连接的覆盖。脚本恢复执行前的环境变量，不输出连接串；普通迁移不播种管理员。

新库由各上下文只创建自己拥有的表。Business 初始迁移不再创建或删除文件表；已执行过旧 Business 初始迁移的数据库保留原有文件表。FileStorage 初始迁移在表、索引已存在时复用它们，并将旧 `FileReferences.Module` 列调整为当前 450 字符模型。超过长度限制或违反新唯一索引的数据会使迁移失败，需先处理，迁移不会删除或截断它们。初始迁移 ID 保留，已经完成的迁移不会重新执行；这不代替旧合并版本升级前的备份与演练。

若已有原合并程序创建的表、但没有当前三个上下文的迁移记录，不要直接重跑初始迁移。应先核对实际表结构与迁移基线；本次不会自动改写历史或搬迁真实数据。旧的拆库 SQL 脚本仅适用于历史独立数据库部署，共用 `Devkit` 时不要执行。

如确需迁移时创建管理员，可在 Identity 命令中明确使用 `-SeedBootstrapAccount`，并通过外部环境变量提供 `BootstrapAccount__UserName`、`BootstrapAccount__Email`、`BootstrapAccount__Password`。不得向 Business 播种身份数据。

认证协议保留 `/api/v1/auth/*` 版本路径、短期 access token、哈希存储且单次轮换的 refresh token 和 ProblemDetails 错误响应。签名统一采用 RS256，Identity 仅持私钥，Business 仅持公钥；旧 HS256 配置不再适用。

业务每次受保护请求通过 `GET /api/v1/auth/permissions` 获取当前身份断言，身份服务负责检查 `auth_version` 和账号状态；业务本地执行能力及资源归属规则。业务不直读身份表或身份缓存。
