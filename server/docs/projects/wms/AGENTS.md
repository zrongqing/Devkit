# WMS 项目协作规则

本项目面向制造业仓库。所有 WMS 专题文档，包括需求、术语、业务流程、接口设计说明和验收记录，统一放在仓库的 `server/docs/projects/wms/`。从[系统需求文档](wms.md)进入业务范围，通过[行业术语表](WMS行业术语.md)核对术语。

## 开始任务

- 遵守[仓库规则](../../../../AGENTS.md)、[服务端规则](../../../AGENTS.md)和[服务端执行约定](../../../../.agents/harness/server.md)。公开接口仍以服务端版本化 HTTP 契约与 OpenAPI 为准。
- 先确定任务涉及的业务单据、操作角色和库存范围。对接生产、质量或 ERP 时，列明谁发指令、谁确认实绩、失败后由谁对账。跨模块可靠交付遵循[既有 MES 约定](../../MES模块化服务与可靠消息框架.md)。

## 维护需求与术语

- 使用中文业务名称，英文或缩写首次出现时写明含义。同一概念沿用术语表名称；新增术语时同时给出现场例子或与相近概念的区别。
- 修改需求时保留已有需求编号，写明触发条件、库存数量或状态的变化、异常处理和可复核的验收结果。特别核对领料交接、实际耗用、余料退回和成品接收各自的时点。
- 把现场已确认的规则、用于评审的假设、后续候选功能分开记录。开源项目提供流程实例，标准提供编码含义；引用时链接至对应源码、官方文档或标准条目，注明借鉴了哪一项。
- 改动数量、单位、可用量或追溯口径时，同时核对需求示例与术语表。用一个批次走完正常流程，再用重复提交、部分完成或差异审批验证边界。

## 进入实现时

- 列表和候选项按工厂、仓库等授权范围查询，遵循[统一分页查询](../../统一分页查询.md)。单据详情、扫码定位、批次追溯和库存调整同样执行数据范围校验。
- 新增或修改服务端接口时同步维护契约、Web 调用模板和相关服务端测试，按上级规则执行构建与测试。Desktop 变更需要用户明确指定。
