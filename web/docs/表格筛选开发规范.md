# 表格筛选开发规范

本规范是新增和修改业务表格的默认规则。基础控件使用 Element Plus；HTTP 契约以服务端 OpenAPI 和 [统一分页查询](../../server/docs/统一分页查询.md) 为准，Web 不重新定义数据访问权限。

## 字段类型与交互

| 字段 | 公共配置 `type` | 控件 | 提交语义 |
| --- | --- | --- | --- |
| 用户名、标题、描述 | `text`，默认 | 文本输入 | `contains/value` |
| 类型、状态、是否启用 | `select` | 可搜索、可清空、多选下拉 | `in/values`，精确匹配编码 |
| 角色、部门等关联 | `select` + `field` + `operator` | 服务端候选，多选下拉 | 集合 `anyOf/values`，提交稳定 ID |
| 数量、大小、版本 | `numberRange` | 最小值 / 最大值 | `gte/value`、`lte/value` |
| 创建时间、发生时间 | `dateRange` | 起始时间 / 结束时间 | `gte/value`、`lte/value`，带时区 ISO 8601 |

选项包含 `label` 和 `value`。显示名称可以中文化、改名，查询始终使用服务端定义的编码或 ID。例如“模块”提交 `module`，“目录”提交 `directory`，角色提交 GUID。禁止从当前页提取选项、将显示值拼成字符串代替精确筛选，或使用页面里的按钮 / 标签文本推断查询值。

输入选择器文字只搜索候选项；选择候选后成为草稿，点击控件后面的筛选图标统一提交全部列草稿。文本输入还支持回车提交；选择器回车用于选择候选。多列条件 AND，同列多选 OR。角色多选默认“拥有其中任意一个角色”，不表示必须拥有全部角色。

空数组、空文本、两端均空的范围不提交条件。布尔 `false` 的编码为字符串 `false`，数字零为字符串 `0`，都必须保留。范围可只填一端，两端同时填写时起始值不得大于结束值；范围边界包含本身，日期控件使用本地时间显示并携带时区提交。

## 公共配置与接入

`DataTable` 提供 `filter-schema`，键是列的查询字段（普通列为 `prop`）；列的 `query-field` 会覆盖该键。未配置字段保持文本行为，操作列不提供筛选。

```vue
<DataTable table-key="example-users" :load-page="tableQueries.users()" :filter-schema="userFilters">
  <el-table-column prop="userName" label="用户名" />
  <el-table-column prop="roles" label="角色" />
</DataTable>
```

```ts
import { computed } from 'vue'
import type { TableFilterSchema } from '../components/tablePresentation'

const userFilters = computed<TableFilterSchema>(() => ({
  roles: {
    type: 'select',
    field: 'roleIds',
    operator: 'anyOf',
    options: roles.value.map(role => ({ value: role.id, label: role.name })),
  },
}))
```

这里 `roles` 列按名称展示和排序，筛选单独使用 `roleIds`。筛选字段覆盖不改变列的排序字段。当前用户管理复用既有 `identityApi.roles()` 的完整角色列表，包含内置与自建角色；角色更新后重新加载候选，不能把“不可分配”角色从可查询候选中排除。

静态字典和常用表格配置放在 `src/api/queryOptions.ts`：`queryDictionaries` 用于候选 / 展示名称，`tableFilterSchemas` 用于表格配置。已有业务 `label()` 也复用该字典；不要在每个页面维护一份相同状态文案。新增类型或状态时，同一个变更更新服务端允许值、Web 字典与契约验证。

公共职责：

- `TableColumnHeader.vue`：列头入口、激活状态、排序与最小宽度。
- `TableFilterInput.vue`：字段控件、候选搜索、错误重试、范围输入。
- `tableFilters.ts`：草稿复制、条件序列化、标签显示。
- `DataTable.ts`：全部条件提交、服务端查询、请求取消、分页及重置。
- `src/api/tableQueries.ts`：请求模板；所有业务 URL 保留在 `src/api`。

## 动态选项与远程搜索

小字典通过独立授权接口完整获取，在浏览器搜索候选；这不属于本地筛选表格记录。大字典应提供受权限限制的服务端候选搜索接口，再配置：

```ts
{
  type: 'select',
  field: 'departmentIds',
  operator: 'anyOf',
  loadOptions: (keyword, signal) => departmentApi.searchOptions(keyword, signal),
}
```

`loadOptions` 返回 `Promise<{value: string; label: string}[]>`，必须传递 `AbortSignal`；上例只是未来部门接口的接入示例，不表示已新增该端点。公共组件提供 250 ms 去抖、取消前次请求、序号保护、加载状态和错误重试；保留已选远程候选名称，避免搜索下一批候选时标签变为 ID。当前角色数量较小，采用完整角色列表，无额外候选端点。

筛选器不能从表格当前页生成下拉选项，也不能只使用角色分页接口的第一页。候选接口独立校验读取权限；角色分配等写操作继续使用原有权限规则。有效但已失效 / 已删除的关联 ID 查询无匹配记录，不回退到同名角色。

## 提交、重置与分页

- 下拉选择与范围编辑只修改草稿；翻页、刷新和排序携带已提交条件。
- 提交前复制数组和范围对象，避免编辑草稿改变正在生效的条件；任意列存在非法范围时阻止整次提交。
- 提交后回第一页，所有列一次请求；最多 32 个条件、8 个排序字段。一个完整范围占两个条件，每个多选条件最多 100 项，每项最多 512 字符。
- 条件标签显示名称而不是编码 / ID，支持逐项移除；移除某列标签时同时清除该列草稿与生效条件并执行查询。
- “清空筛选”清除文本、多选、范围及页面外部条件后查询；列宽、显示列、固定偏好和资源上下文保留。“重置表格”另外恢复排序及布局偏好。
- 服务器完成筛选、统计、排序与分页；禁止浏览器对当前页记录执行二次筛选或排序。
- 菜单树按根节点分页，保留匹配节点祖先；筛选模块时可见目录作为祖先属于预期行为。
