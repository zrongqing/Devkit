# Web 协作规则

- 保持 Vue 3 + TypeScript；新增依赖前先记录技术选型理由。
- API 调用集中在 `src/api`，不要让组件直接拼接业务 URL。
- 与后端契约同步变更：先更新 OpenAPI/DTO，再更新调用端；涉及服务端接口变更时必须同步新增或更新服务端接口 / 契约测试并运行；纯 Web 测试仍仅在用户明确要求或专用流程固有要求时执行。
- 基础 UI 组件库统一使用 Element Plus 与 `@element-plus/icons-vue`；布局、表单、弹窗、反馈等优先复用其组件。路由与状态管理沿用 `TECH_STACK.md` 中已记录的选型。

## 页面布局

- 工作台页面默认铺满当前选项卡的可用宽高，统一保留内边距；页面根容器不得设置 1120 / 1320 px 等居中最大宽度限制。表单字段和阅读内容可按需限制自身宽度。
- 工作台页签样式仅作用于直属页签面板，不能污染页面内嵌页签。固定工作台外框高度，内容在当前选项卡内滚动，宽表格在表格内部横向滚动；使用 `min-width: 0` / `min-height: 0` 保证弹性布局可收缩。

## 表格规范

- 业务表格统一复用 `src/components/DataTable.ts`，基于 Element Plus Table；每个表格必须提供稳定、唯一的 `table-key`，不能使用数组下标或随数据变化的值。
- 默认服务端分页，每页 20 条，允许切换 10 / 20 / 50 / 100 条；`DataTable` 必须提供 `load-page`，只显示服务端返回的 `items`，总数使用 `total`。不得对当前页再次进行本地筛选、排序或切片。数据减少时修正页码，筛选、排序或页大小改变时回到第一页。
- 列头显示清晰的列间分割线，筛选和排序按钮始终显示，无需悬停；生效筛选和排序方向保持蓝色高亮，并显示排序优先级数字。表头不放锁定按钮，固定位置与显示列统一在“表格设置 → 列设置”管理。控件与列名保持同行、预留空间，避免交互时跳动。排序使用上下三角与优先级数字，最多 8 列。
- 输入框后提供筛选图标；键入只更新草稿，点击图标或回车才一次提交所有列条件。多列条件按 AND 合并，清空后也需提交；改变排序 / 翻页继续携带已提交的条件。筛选入口保留在列头，表格顶部不新增通用搜索框或“筛选”按钮。
- 默认仅固定首个关键数据列在左侧，操作列在右侧；通过 `search-field` 可指定关键数据列。容器窄于 720 px 时暂时解除固定，避免遮挡内容，并保留偏好。列设置支持隐藏数据列（至少保留一个）、固定左侧 / 右侧 / 不固定；偏好按 `table-key` 和稳定列标识缓存。兼容旧布尔固定偏好，缓存损坏不阻断页面。
- 列间边界支持拖动调整列宽，包含数据列、操作列和选择 / 展开辅助列；最后一列的右边界禁止拖动，不能通过拖动表格外边界拉伸表格。使用 Element Plus 原生列宽拖动，启用边框与 `resizable`，设置 `allow-drag-last-column=false`；辅助列在公共组件中统一启用。
- 列宽按稳定 `table-key` 与 `column-key`（普通列可用 `prop`，辅助列使用类型标识）分别保存到 localStorage，不能使用列下标。刷新、重进页面、分页、筛选和排序均保留列宽；拖动列宽不触发服务端查询。“重置表格”同时恢复默认列宽并清除对应偏好。
- 顶部统一提供刷新、“表格设置”及业务操作，不提供通用搜索框和“筛选”按钮；列头保留组合筛选能力。页面通过 `filters` / `toolbar` / `actions` 插槽直接展示已有业务下拉选项、资源上下文和新增 / 上传等操作，避免重复工具栏。筛选条件以可关闭标签展示，支持逐项移除和清空；外部条件用 `external-filters` / `remove-filter` 同步。底部仅保留总数与分页。
- “表格设置”收纳列设置、自动适应列宽、重置表格。“清空筛选”清空所有列草稿和已提交条件，通过 `reset-filters` 同步页面筛选器，回到第一页执行一次查询，保留排序、列宽、固定及资源上下文。“重置表格”同时恢复默认显示列、固定、列宽与排序。
- “自动适应”根据完整列名和当前页可见单元格的实际内容（含标签、按钮、图标、内边距）计算列宽，保留表头最小宽度并自动缓存；不请求全部数据或触发查询，不重新挂载表格。自动适应列宽通常不超过 480 px（完整表头所需最小宽度更大时优先保证表头）；超长内容通过省略号和悬浮提示查看，继续使用内部横向滚动，保持最后一列右边界不可拖动。
- 列的最小宽度必须容纳完整列名、筛选 / 固定 / 排序控件及优先级数字、间距和单元格内边距；通过实际渲染尺寸测量，标题单行完整显示，不能用省略号或换行替代。拖动和恢复缓存都不得突破此最小宽度，历史缓存过窄时自动抬高。
- 缓存仅接受有限数值且校验范围（40–10000 px）；无效缓存忽略，存储不可用时仍允许本次调整；避免通过重新挂载表格应用列宽而产生闪烁。
- 页面显式声明的 `min-width` 是列宽下限，拖动、自动适应和恢复旧缓存都必须遵守。操作按钮组保持单行、垂直居中；列宽应足以容纳按钮组，多个次要操作使用“更多”菜单，不能靠自动换行堆叠。
- 表格容器宽度随可视区域自适应，列总宽度超过容器时自动显示表格内部横向滚动条，不得压缩到最小列宽以下或撑宽整个页面。窗口、侧栏、页签或弹窗尺寸变化时使用 Element Plus 的自适应布局重新计算，保持本地列宽偏好。
- 普通字段必须声明 `prop`；自定义展示列提供稳定的 `column-key`，通过 `query-field`（默认取 `prop` 或 `column-key`）对应服务端明确支持的字段。`:table-value` 仅标识自定义展示列，不可用于本地筛选排序。操作列仅提供固定控制，不对按钮筛选或排序。
- 树形表格保留父子关系，按顶层节点分页；筛选保留匹配节点的祖先，排序只在同层进行。不得因筛选修改业务对象或影响权限及删除条件。
- 查询调用集中在 `src/api/tableQueries.ts`，遵循服务端 `PageQuery` / `PageResult<T>` 契约；请求带齐已提交筛选条件及排序数组。使用 AbortSignal 和请求序号避免旧响应覆盖新查询，展示加载 / 失败 / 重试状态；权限由服务端最终校验。

- 表头保留列间分割线，内容区使用浅色横向分隔线和行悬停反馈、弱化竖线；表格行默认水平左对齐、垂直居中，明确声明对齐方式的列按声明执行。长文本和多标签内容单行省略并提供完整提示，复杂内容保留展开行 / 详情入口，避免一行按钮挤满操作列。
